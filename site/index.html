01Principles

核心思路

五个原则贯穿设计：编排用代码，边界留给人，核心不依赖界面。

用代码组织工具

模型写短段 Luau 脚本，把读取、分析、修改和验证组织起来——这就是 CodeMode。

for _, f in files do   cayw.call('check', f) end

控制权留给用户

文件访问、工具调用、操作确认和资源预算都有明确边界；一段脚本获准，不等于放行其中每一步。

权限审批取消预算

核心独立运行

对话与工具执行不依赖终端、网页或插件。界面是入口，不是核心运行的前提。

会话不绑死在进程上

保存任务与执行记录；恢复时先核对已经发生的操作，不盲目重复执行。

按需组合能力

通过公开接口接入模型、工具和插件；终端、网页与自动化程序共用同一套可独立运行的核心。

02How it works

怎么工作

模型负责组织步骤，CAYW 负责检查并执行每一次工具调用。

  1. 01

    模型服务

    理解任务，产出编排步骤与 Luau 脚本。

  2. 02

    会话与事件

    记录对话、尝试与执行事实，支撑恢复与核对。

  3. 03

    CodeMode

    在受控环境中运行 Luau，把多次工具调用组织成可验证流程。

  4. 04

    统一管控

    权限 · 审批 · 取消 · 预算——每次 cayw.call 独立过检。

  5. 05

    受控工具与本机执行

    文件、检索、Git、构建/测试等能力在边界内执行，进程可回收。

一段脚本，多次独立检查

脚本获准运行，并不意味着其中每一步都被放行。CAYW 在每一次 cayw.call 上执行同一条管线：

  • 1参数检查
  • 2授权与审批
  • 3预算检查
  • 4结果记录
CodeMode · Luau 示例 
local files = cayw.call('fs.glob', {
  path = '.', pattern = '**/*.rs'
})
local matches = cayw.call('fs.grep', {
  path = '.', pattern = '^pub fn', multiline = true,
  max_matches = 20
})
return { files = files, matches = matches }
