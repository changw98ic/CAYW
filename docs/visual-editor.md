# 当前页面的可视化编辑

本功能由 [Issue #30](https://github.com/changw98ic/CAYW/issues/30) 跟踪。HTML/CSS、Vite React JSX/TSX 和 Vue 3 页面已支持源码编辑。操作、保存、停服、重启和再次编辑已在 macOS ARM64 上实际运行。最新精简与重测结果见[本轮验收记录](validation/issue-30-editor-simplification-macos.md)。框架适配和真实模型状态见[框架验收记录](validation/issue-30-framework-editor-macos.md)；较早的 HTML 首版结果见[历史记录](validation/issue-30-visual-editor-macos.md)。启动方式见[应用说明](../crates/cayw-visual-editor/README.md)。

## 首版路线

支持已有的 HTML/CSS 页面，以及使用 Vite 的 React JSX/TSX、Vue 3 单文件组件项目。页面不需要预先注册组件，也不需要改成低代码模板。编辑器在运行页面上显示选区，并标出对应的源文件和行号。项目原有的样式、组件脚本和事件继续加载。HTML 默认直接打开；React 和 Vue 分别使用 `--framework react`、`--framework vue`，启动方式见[应用说明](../crates/cayw-visual-editor/README.md)。

编辑器是可选应用 `cayw-visual-editor`。文件读取和保存使用 `cayw-host` 的公开 Rust 接口，接受权限检查、调用记录、取消和预算约束。Core 不依赖编辑器。普通属性和结构操作不调用模型。

编辑器页面与项目预览使用不同的本机地址。编辑器访问令牌只保存在编辑器页面的内存中，不放入项目页面、地址栏或浏览器存储。桥接脚本先于原页面脚本建立一次私有消息通道；父页面核对来源、预览窗口和当前页面地址，后续编辑消息只走该通道。项目脚本直接发送的窗口操作消息不会成为编辑请求。页面脚本仍在运行，这不是运行恶意页面的安全沙箱。

## 编辑操作

1. 打开当前项目页面预览，点击“可视化编辑”。页面内容与布局保持原样。
2. 悬停查看边界，点击选择元素，或选择父容器。
3. 拖拽调整元素顺序，或移动到适用的静态容器。放下前显示落点。
4. 右键修改颜色、宽高、字体、内容和布局。改动写到选中元素的源码。React/Vue 修改组件定义；同一源码同时渲染多个实例时保持只读。
5. 从选区附近的“+”或右键菜单插入组件。基础元素与区块使用本项目实现的 HTML/CSS，按项目转换为 JSX 或 Vue 模板语法，不引入组件库依赖。
6. 使用撤销、重做和桌面／移动宽度预览检查结果。切换到交互预览以操作原有按钮、链接和控件。
7. 点击保存，将改动写回 HTML、JSX/TSX 或 Vue 源文件。刷新或重启预览后，可以再次进入编辑并继续修改。未保存草稿与撤销历史只在本次进程内存中。每次修改后会重载预览，不保证保留计数器等临时运行状态。

## 保存与冲突

项目源码是保存结果的依据。编辑器保留打开文件时的内容摘要。保存需要通过 Host 的 `expected_sha256` 检查。文件被外部修改后，保存被拒绝，草稿保持锁定；只有明确重新加载源码，才会刷新映射并允许继续保存。元素标识同时绑定当前草稿摘要，另一个标签页持有的旧选区不能误改重新编号后的元素。

HTML 按单个页面文件编辑。React/Vue 可以编辑同一项目的多个组件文件，一次操作只改变一个文件；不支持跨文件移动元素。样式操作修改选中元素的内联样式，不直接改共享 CSS 或 Vue 的 scoped 样式块。内联样式可能覆盖媒体查询中的同名属性，用户需要在移动宽度下检查结果。

框架项目保存前核对文件清单中的磁盘内容，再逐个写入脏文件。每个文件都有独立摘要检查。若已有文件写入后，另一个文件保存失败，应用会记录部分保存并停止写入，不能宣称全部回滚或完整保存成功。

Host 的文件锁协调使用同一约定的写入者。外部编辑器可能不使用该锁；内容摘要检查不等于与任意外部程序之间的文件系统事务。

保存结果无法确认时，应用必须保留未知状态并停止继续写入。重启不能自动清除未核对的操作记录。

## 可编辑范围

首版支持源码中具有明确边界的 HTML 元素。文本修改不能删除无关的嵌套元素、事件属性或脚本。移动只适用于可以可靠映射的静态结构。

脚本生成或重复克隆的元素、模板表达式、Shadow DOM、Canvas 和嵌套页面不能直接假定有唯一的源码目标。无法可靠映射的区域应保留原有显示，并说明当前不能执行的操作。其他区域可以继续编辑。

React 只映射原生 JSX/TSX 标签，Vue 3 只映射单文件组件的模板部分。脚本、类型声明和原样式块保留。静态文字和样式可修改，原事件处理器保留；动态文字、动态样式和动态属性只拒绝对应操作。循环、条件分支和属性展开区域只读。含事件、表达式或组件子树的结构不能任意移动、克隆或删除。

React 样式写成框架要求的对象。当前不接受含 `!important` 的 React 样式修改，以免保存后被 React 忽略。插入 Vue 区块时，区块自带的静态 CSS 写入同一单文件组件的普通样式块；原有 script、scoped、module 和带媒体条件的样式块保留。

框架预览使用项目已有 Vite 配置、插件、别名和资源，分别启动普通预览与草稿预览。Vite 缓存放在项目外的状态目录。Node 进程不继承编辑器令牌或模型凭据，但项目构建配置仍以本机用户权限运行，不是沙箱。编译进程停止后，编辑和保存返回不可用；可查看最后草稿并重启编辑器。这种已知停服与磁盘保存结果未知是两种不同状态。

普通编辑请求断网或返回临时服务错误时，界面显示错误并允许继续操作。操作响应丢失或无法识别时，界面重新读取当前草稿，不重发原操作。如果草稿读取也失败，界面返回连接页；重新连接会读取服务中保留的草稿。它不会仅凭这些错误推断源码保存结果未知或编译进程已停止。保存请求断网，或服务明确报告结果未知时，仍需先核对保存结果。

样式输入支持浏览器识别且源码编辑器可写回的 CSS 值，包括 `calc()`、`clamp()` 等表达式。字号、宽高、行高和网格列数不再设置额外的任意数值上限。裸数字长度自动补 `px`，行高保留倍数写法。

当前不适配 Svelte、Next.js/Nuxt 服务端渲染、服务端模板或任意构建系统，也不声明跨框架通用转换能力。

## 方案依据

- Onlook 的元素标记、源码索引和结构化修改方式可作设计参考。它的 React/TSX 路线不能直接当作 HTML/CSS 实现。
- Puck 以注册组件和页面数据为基础，不能独立完成任意已有页面的源码映射。
- GrapesJS 可以导入 HTML/CSS，但导入后重新输出页面不等于保留原工程中的脚本和源码位置。
- shadcn/ui 与 Magic UI 的开源代码使用 MIT 许可证，但需要按组件接入 React、Tailwind 及其他依赖。首版原生 HTML/CSS 组件由本项目实现，不复制这些库的组件代码。
- UI TripleD 作为区块和动效方向参考。React Bits 当前许可包含组件再分发限制，本次不复制其组件。

参考文档：[Onlook](https://github.com/onlook-dev/onlook#how-it-works)、[Puck](https://puckeditor.com/docs/integrating-puck/component-configuration)、[GrapesJS](https://grapesjs.com/docs/)、[shadcn/ui](https://ui.shadcn.com/docs/installation/manual)、[Magic UI](https://magicui.design/docs/installation)、[React Bits 许可证](https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md)。文档调查只说明选型依据，不代表已安装或验收这些集成。

## 验证范围

当前只验证 macOS ARM64。其他 macOS 架构未验证。真实模型调用不属于普通编辑验收。

真实页面验收使用了仓库 `site/` 和固定版本的 StartBootstrap Agency 工作副本。两者都没有编辑器预接入标记。`site/` 覆盖卡片、按钮、布局、输入组件、保存和重启；它没有原生 `<img>`。Agency 单独验证已有图片替换、原模态窗口和移动导航。Agency 保留了外部脚本和字体请求；本次部分字体下载失败，不宣称完全离线或外部字体全部可用。

合成页面单独验证动态生成、重复克隆、模板、Shadow DOM、Canvas、子页面只读，以及绝对定位、半透明颜色和含内边距容器缩放。解析器、权限、过期映射、并发和未知状态有独立 Rust 回归。

React/Vue 验收使用本项目从零编写的 Vite 测试项目。React 同时覆盖 JSX 与 TSX；Vue 覆盖单文件组件模板及原脚本、局部样式保留。两个项目均实际完成多文件修改、保存前磁盘不变、保存后构建、停服重启、再次编辑、外部修改冲突，以及原计数器和表单提交。它们是合成输入，不能当作外部项目或真实模型生成结果。最新命令、源码与构建摘要、截图、保存差异和调用记录见[精简重测记录](validation/issue-30-editor-simplification-macos.md)，适配阶段的结果见[框架验收记录](validation/issue-30-framework-editor-macos.md)。

真实模型生成是独立验收。用户已授权本次 Magpie 调用最多 100,000,000 token，包含失败与未知预留。当前环境没有 `MAGPIE_API_KEY`，真实生成请求为 0 次。公开接口探测、脚手架构建和离线账本导出已运行，但模型生成项目后的编辑、保存与重启仍未验证。

外部工程与 Linux 可复跑入口见 [F18 外部工程验收补强（SLICE L）](validation/f18-external-project-validation.md)：对传入 Vite React/Vue 路径做结构检查与编辑器 HTTP open/edit/Host-save/reopen；缺 Issue-30 fixture id 的外部工程不误失败；不宣称 Magpie 生成通过。macOS Magpie 凭据经 `scripts/load-gateway-magpie-env.sh` 映射，证据不打印密钥。
