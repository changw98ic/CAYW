### 有限额度恢复方式

现有代码在任何旧模型预留未知时拒绝后续请求。单纯提高启动配置不能恢复。本次补充一个可信 Rust 宿主入口，将后续额度绑定到同一 Session 的一个明确新 Task，同时保留旧预留与原记录。

新入口先核对原执行者停止、所有旧预留的完整身份和游标，再保存授权人、依据、目标 Task 与有限额度。后续每个请求继续占用同一预算树。新请求若也失去最终用量，执行再次停止。新 Task 不复活原 Future 或丢失的 VM 栈，不自动重放旧工具。

原数据库已通过公开 `Runtime::recover` 核对停止的执行者。原 Task 变为 `interrupted`，不改写原失败事实。后续任务全部在原 Session 内执行，没有 Fork，也没有将新 Session 的结果当作恢复证据。
