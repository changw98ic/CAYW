# 审批等待、终态展示与 Trace 性能修复验收

日期：2026-11-18。平台：macOS arm64，Rust 1.95.0。本记录只覆盖下列源码、构建和场景，不外推到其他架构。

## 修复内容

- Host 在授权和执行通道排队结束后才启动单次执行计时。等待仍接受取消和任务总时限。授权、调用配对、执行时限、未知副作用核对保持原有要求。
- Runtime 将已知停止原因传给 Agent，避免内部失败被写成用户取消。
- WebUI 从持久执行记录更新工具卡片终态，保留原工具返回值；重连快照不会被较旧事件覆盖。Run Inspector 使用首次终态时间计算完整耗时。
- Trace 页面传输变化的项目投影，展开证据时读取原始事件。采集器读游标不再复制全部记录。SQLite 事务追加事件、更新变化的投影，避免每批重写全部历史。
- 旧 Trace JSON 原样归档后迁移为 SQLite；迁移后的路径只有 SQLite 实现。写入失败整笔回滚，进程内状态与持久状态都不前移。新增依赖沿用工作区已有 rusqlite 0.40.1 / libsqlite3-sys 0.38.2，均为 MIT。
- 模型可通过统一 Host 调用 artifacts.put/list、plannotator.list 和 session.run_inspector。会话身份从当前执行继承，不由模型提供。模型不能借此填写宿主反馈或用户验收。
- 整题产物补齐任务/事件分页与 SSE 分批连续回放。原始失败工作区保持不变；修复后的完整源码单独交付。

## 性能与存储

`evidence/storage-benchmark.log` 使用旧失败任务追踪文件的副本，包含 50694 条原始事件、54 个项目；追加一个合成事件后重启核对 50695 条全部保留。

- 全量 JSON：30681677 字节，序列化约 797.5 ms。
- 首次页面状态：477114 字节，约 11.65 ms。
- 无变化状态：157 字节，约 0.026 ms。
- SQLite 追加一个事件并提交：约 24.5 ms；数据库文件前后均为 38670336 字节，复用了已有页空间。

这是本机单次实测，不是延迟保证，也不是旧、新磁盘写入的同条件吞吐对照。测试没有固定毫秒级断言。原始事件仍驻留采集进程内存；超长历史的内存占用和首次加载仍随记录增长。

真实模型使用冻结构建，包含 Host、Runtime、WebUI、Inspector、原生工具和页面增量协议修复。SQLite 存储改动在其后完成，单独通过最终源码测试、真实历史文件迁移和追加/重启验证，不能声称真实模型任务使用了后续 SQLite 构建。

## 检查与新增边界

新增数量上限、重试和降级：无。新证据请求沿用现有页面请求的 12 秒外部调用时限，超时明确显示读取失败，可由用户重新展开。可能影响响应超过该既有时限的单条证据读取，不丢弃磁盘记录。

新增校验仅针对外部数据：模型工具参数及会话范围、读取事件的身份、SQLite 格式版本和记录身份。依据是统一 Host/会话隔离合同和迁移后读取的完整性；不收紧正常调用的数量或大小。生成产物新增分页游标校验，非法游标报错，合法数据通过续页全部可取。

最终检查结果及日志见证据目录的 `final-checks.json`。首次全量检查开始后新增了 SQLite 依赖，导致其末尾 rustdoc 使用旧依赖图失败；该日志保留在 `workspace-tests.log`，最终源码独立重跑结果保存为 `workspace-tests-final.log`。

未验证：其他 macOS 架构、手机真机、多机队列。生成任务台仍是单机原型；本次未实现生产身份系统、分布式 worker 或无限历史列表的虚拟滚动。

检查中还确认了既有 `user.ask` 边界：协作服务为确保已知取消先于 Host 的未知结果处理，仍使用单次 Host 时限的 3/4 提前结束等待。这是另一条服务专用计时路径，本次未重构其已知/未知结果结算机制；不能把本记录解释成仓库中所有重复计时均已消除。

最终全量 Rust 测试：3136 项通过，11 项忽略；命令退出码 0。格式、workspace check、Clippy、offline 示例、116 项 WebUI JavaScript 测试均通过。
