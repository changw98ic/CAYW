# 真实交互、长任务与恢复手册

[返回主方案](../product-eval.md)。U01 与 L01 都必须使用真实模型，保留真实界面/运行证据。静态截图、Playwright 的固定 Provider 回归、SDK 成功返回，均不能代替以下效果验收。

## U01：把同一任务交给真实用户界面

U01 使用准备脚本给出的 CSV 任务及产物检查。分别建立全新 TUI/WebUI run，使用相同模型、输入、预算和审批策略。界面证据不能从 CLI lane 复制。记录 macOS 版本/架构、终端或浏览器版本、窗口尺寸、字体/缩放、网络/模型首 token 延迟。

主手册启动独立 Client 后，用同一环境连接：

```sh
"$BIN/cayw" tui --workspace "$RUN/workspace"
# 或在另一全新 U01 run 打开 WebUI：
"$BIN/cayw" --ui web --no-open --workspace "$RUN/workspace"
```

WebUI 使用命令返回的普通本地 URL，不猜地址，不加 `--lan`。浏览器只能接入同一 Client 管理的工作区，先检查屏幕上的工作区身份。TUI 在输入框发本 case 原始提示；WebUI 使用其真实输入界面。不得后台 CLI 提交后仅截一个 UI 最终状态来声称完成全交互。

### 录制顺序与观察点

1. 启动/连接/新建 Session，确认工作区与模型可辨认，输入草稿可读，键盘焦点明确。
2. 发送本 case 提示，记录点击/按键至首次可见反馈、首次模型内容、最终可交付结果的时间；模型等待与 UI 无反馈分别记录，不设不稳定毫秒断言。
3. 至少真实检查一个待审批调用。用户能否知道操作、路径、范围及原任务？批准一次；在单独安全子场景拒绝一次非必要操作，观察结果及模型后续解释，不能为了截图批准危险操作。
4. 检查流式文本、文件/变更/日志及最终产物。TUI 用 Alt+1/2/3/4 查看 Chat/Files/Diff/Logs；这些视图是只读，不把它们当编辑器。WebUI 只测实际存在的对应控件，不杜撰按钮名。
5. 长输出滚动、切换 Session、窗口缩小和恢复。观察截断、重叠、重复段落、滚动跳跃、代码/路径不可读等问题；截图标注真实窗口尺寸。
6. 在单独可取消运行中，TUI Ctrl+X / WebUI 实际取消控件请求取消。记录“请求取消”和“原任务已终止/清理完成”是否可区分。不要把 Ctrl+Q/Ctrl+C 退出 TUI 当成取消 Task。
7. TUI Ctrl+R 重新连接；WebUI 刷新/重连。核对已消费事件与权威快照，确认没有重复提交、丢草稿（如该场景承诺保留）、旧任务内容串到新 Session。终端退出后检查状态恢复正常。

浏览器刷新不保证与 TUI 草稿保留语义相同，应记录实际行为，不预设通过。模型预算出现 unknown 时，单独记录 UI 展示的原预留、未知请求数、一次性新增额度与累计上限，拒绝后草稿和 Task 是否符合实际合同。没有触发该场景则标未测，不能通过写一句“支持预算确认”计分。

### UI 人工 rubric（每项 0–4）

| 维度 | 0 分 | 2 分 | 4 分 |
| --- | --- | --- | --- |
| progress：状态与进度 | 错报完成/不知是否运行 | 能识别状态，但长等待或阶段信息难理解 | 运行、等待审批、取消中、结束/失败清楚，能定位正在做什么 |
| control：审批及取消可控性 | 看不清目标/误导授权 | 能决定但需要另外查日志 | 操作、参数、范围、原任务和决定反馈清楚，无隐藏风险 |
| workspace_clarity：工作区及产物清晰度 | 结果不可读或找不到 | 可读但滚动/截断/格式有明显障碍 | 回复、文件、diff 与日志易读，能找到交付物并核对 |
| error_recovery：错误与重连恢复反馈 | 假成功/重复提交/丢状态 | 最终可恢复，但过程不清楚或需人工排查 | 意图/终态/清理区分明确，重连连续且不重放 |
| discoverability：入口与交互可发现性 | 常规任务无法完成 | 可完成但需明显绕路 | 无非必要绕路，焦点/导航/错误恢复自然 |

以上对应 record.review.ui_rubric 的五个固定键，不另造字段；内容可读性也记入通用 clarity 评分。1/3 分为相邻锚点间的明确表现。每项附至少一处截图时间戳或录屏时间段和事件关联。评审最好由非开发本人独立复核；UI 总评和任务正确性独立报告。字体主观偏好与阻断功能的可用性问题分开。没有真实屏幕证据就保持未验证。

## L01：分阶段产物、中断、重开与显式继续

准备脚本提供 12 个分片台账及全量汇总任务。先用一个独立 run 无中断完成，取得同预算基线；再用全新 run 做中断变体，至少三组。预先固定触发点，例如“第三个分片产物已从工具结果和磁盘确认，后续工作仍在运行时”，而不是运行后挑最有利时机。若模型一次提交全部产物而错过触发点，记中断场景未覆盖，不假造中断成功。

不得在 Agent 运行期间人工补写或修正产物。每个阶段保存文件清单、SHA256、原工具结果及时间戳。中断前可由可信运行者只读采样目录，记录采样时任务仍在运行；不要把中间态误当最终产物。

### A. 受控取消

从 prompt 输出取得原 Task id，在另一终端对**这个 Task**发取消：

```sh
"$BIN/cayw-client" --workspace "$RUN/workspace" cancel \
  --session "$SESSION" --task "$TASK"
"$BIN/cayw-client" --workspace "$RUN/workspace" get --session "$SESSION"
"$BIN/cayw-client" --workspace "$RUN/workspace" tasks --session "$SESSION"
```

也可在原 `cayw-client prompt` 终端 Ctrl+C；客户端保留原身份并等待清理。迟到的取消不可转向新任务。cancel ack 仅表示收到意图；保留实际终态、Device 进程清理和文件证据。draining/unknown 不能记为成功取消。记录取消后完成了哪些已在提交中的写入，不假定所有效果回滚。

### B. 安全停止、重开和核对

待原任务状态与清理明确后，正常停止独立 Client。不要删数据库、换工作区路径或生成新 CAYW_HOME；使用同一构建和配置重启：

```sh
"$BIN/cayw" serve --workspace "$RUN/workspace"
# 另一终端：
"$BIN/cayw-client" --workspace "$RUN/workspace" get --session "$SESSION"
"$BIN/cayw-client" --workspace "$RUN/workspace" tasks --session "$SESSION"
"$BIN/cayw-client" --workspace "$RUN/workspace" recover --session "$SESSION"
```

`recover` 是已有控制命令，用于恢复核对，不会自动重放提示或清除未知效果。先阅读任务、events/audit 与实际文件；失败保留原错误，不反复调用以求“变绿”。恢复页游标按主手册读取。新连接必须继续使用原 Session 和原事件游标，不能偷偷新建 Session 丢弃历史。

当前 `cayw-client` **没有独立 `resume`/`enqueue` CLI 命令**；已有 `task.resume` 是 SDK/IPC 接口。不要写 `cayw-client resume`。此默认 lane 验证的是取消后持久状态核对，以及用户**显式发新一回合**继续未完目标，不宣称同一 Task 原地恢复。

只有确认没有待结算工具副作用，且模型用量预算允许继续后，发送明确的新回合，例如：

> 先核对先前工具结果和磁盘上的已完成分片，不重复已确认的副作用。完成原任务剩余分片和全量汇总，明确列出本回合新增、沿用及无法确认的内容。

该新回合会建立新 Task，原取消 Task 仍保留。原任务文本及新增继续文本都归档。若历史模型费用 unknown，需要新增预算授权，默认 CLI 没有该独立控制命令：在真实 TUI/WebUI 使用既有确认流程，或将 CLI 继续 lane 标 blocked。不能通过新 Session、Fork、提高配置上限或重建数据库抹掉未知费用。

### C. 非正常断连/崩溃（可选，单独授权）

只有隔离机且所有副作用限于 fixture 时，才做关闭执行连接或指定原 Client 进程的故障注入。预先保存进程身份、Task/Attempt、触发点和可恢复备份，不杀其他用户进程。它与正常取消、正常停止分开报告；本 PR 不提供自动强杀脚本，也不强制执行此变体。

重开后若存在 unknown，正确行为可能是阻止继续并要求可信核对，而不是“自动恢复成功”。核对先前已提交的文件和原进程清理，不能仅删除锁/状态就再跑。若缺少安全 reconciliation 入口或无法证明原进程已停止，该子场景 blocked，并记录尚缺的能力。进程强杀通过也不证明断电安全。

### L01 判定

- 所有分片及总汇总正确，阶段结果与最终报告一致。
- 中断前已完成的事实在恢复后可查，未完成部分不被显示为完成。
- 已确认副作用不被盲目重复；如模型重新计算纯只读数据，作为效率开销记录，不等同危险重放。
- 拒绝或 unknown 不被静默忽略；新回合与原任务身份、额外授权和成本可追溯。
- 分别报告：任务最终成功、取消可控、持久状态可读、显式继续成功、同 Task 自动恢复（本默认 lane N/A）。不能用其中一个通过替代其余。
